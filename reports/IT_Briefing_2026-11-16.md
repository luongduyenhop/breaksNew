## 3. TƯ DUY & CÁCH ÁP DỤNG

### Thay đổi tư duy cốt lõi (từ cộng đồng & chuyên gia)
1.  **Từ "Task Executor" → "Problem Owner / System Thinker"**:  
    *Theo cựu Principal Engineer Amazon (VGU Alumni)*: "Tìm *Minimum Acceptable Effort*. Loại bỏ công việc thay vì tự động hóa nó. Đứng trên vai người đi trước."  
    → **Hành động**: Trước khi code task nào, hỏi: *"Vấn đề nghiệp vụ cốt lõi là gì? Có cách giải quyết 0 code không (config, script, loại bỏ feature, dùng tool có sẵn)?"*.

2.  **Từ "Viết code chạy được" → "Viết Spec/AC cho AI Agent chạy được"**:  
    *Theo Steve O (Dev.to)*: "AI không hỏi lại. Mọi gap trong AC đều bị AI lấp bằng 'plausible guess'."  
    → **Hành động**: Mỗi task/Jira ticket bạn nhận/viết, ép buộc phải có: **Outcome có thể quan sát (Observable), Input/Output contract, Edge cases, Rollback plan**. Viết theo format: `Given [context] When [action] Then [observable outcome]`.

3.  **Từ "Chuyên sâu 1 stack" → "T-shaped: Deep Java/Spring + Broad AI/Infra/Security"**:  
    *Theo Ambuj Sir (BMW)* & *Kushal Vijay (Microsoft)*: "Strong Engineer = DSA + Projects + Understanding Business + AI Literacy".  
    → **Hành động**: Giữ Java/Spring làm "Deep". Mở rộng "Broad" bằng: **Python (AI tooling), Network Security (Infra), System Design (Architecture)**.

4.  **Từ "Passive Learner" → "Builder in Public / Open Source Contributor"**:  
    *Theo Gennady Korotkevich (Cognition AI)*: Anh dùng tư duy CP (Competitive Programming) - *simplify, first principles* - để train Devin.  
    → **Hành động**: Build side project **có thật**: *Một AI Agent tự động review PR Spring Boot theo coding standard nội bộ + check security misconfig (dùng Semgrep/Checkov) + gợi ý fix*. Push GitHub, viết blog technical.

> **Kiểm tra dữ liệu**: Không mục nào có `is_major_incident = true`. Các sự cố Microsoft, PostgreSQL (J2TEAM post item 6, 7) được nhắc trong tin tức/thảo luận nhưng **không được đánh dấu là major incident có CVE/KEV cụ thể trong dataset này**.
